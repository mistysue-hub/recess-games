Day One at the Studio

Ships today

a window, a square named Blip that you can steer, and your first Lua.

Welcome to Pixel Forge. We're a two-person studio (now three, counting you). I'm the lead dev. Jamie does the art, names every variable thing, and has never once admitted to a bug. You'll meet Jamie's code soon.

Here's where you'll be by Build 03: a ship, a sky full of rocks, sound effects you made yourself, and a game-over screen that insults you. Three builds. Every one of them starts the same way: a folder with a file called main.lua inside. That folder is the game. We don't use a giant engine; we use LÖVE, a small free framework that runs the Lua language, and we write in VS Code.

Step 1Install the tools (ask a grown-up to sit with you)

This is the boring twenty minutes. I won't pretend otherwise. Get through it once and you never do it again.

  1. LÖVE 11.5 from love2d.org. Windows: the 64-bit installer. Mac: drag the app into Applications. Linux: use the package for your system.
  2. VS Code from code.visualstudio.com.
  3. Inside VS Code, open the Extensions panel (the four-squares icon on the left), search Love 2D Support by Pixelbyte Studios, and install it. This gives you one shortcut: Ctrl+L (Windows/Linux) or Cmd+L (Mac) runs whatever game folder you have open.
  4. Mac only: the extension needs to know where LÖVE lives. Open VS Code settings, search "pixelbyte", and set the path to /Applications/love.app/Contents/MacOS/love.

Make a folder on your computer called pixel-forge. Inside it, make another folder called build01-blip. In VS Code, choose File → Open Folder and open build01-blip. Everything you type today goes in a new file there named exactly main.lua.

Step 2The three functions every LÖVE game has

A game is a flipbook. Sixty times a second, LÖVE asks your code two questions: what changed? and what should I draw? You answer with three functions.

function love.load()
  -- runs once, when the game starts
end

function love.update(dt)
  -- runs every frame: move things, check things
end

function love.draw()
  -- runs every frame, after update: draw everything
end

Type exactly that into main.lua, save, and press Ctrl+L / Cmd+L. A black window should open. Congratulations: that's a game with nothing in it. Technically it has a perfect review score, since nobody has found a bug yet. Close it with the window's close button.

If nothing opens, the three usual reasons are: the file isn't named main.lua, VS Code has the wrong folder open (the folder must be the one that holds main.lua), or LÖVE isn't installed where the extension expects.

Step 3Meet Blip

Blip is a square. In Lua, a thing with several facts about it is a table. Tables use curly braces, and each fact has a name.

function love.load()
  blip = { x = 400, y = 300, size = 24, speed = 200 }
end

Now draw it. The window is a grid of pixels. 0, 0 is the top-left corner. x grows to the right. y grows downward (this surprises everyone; it's just how screens count). Our window is 800 wide and 600 tall, so Blip starts in the middle.

function love.draw()
  love.graphics.setColor(0.2, 0.9, 1)
  love.graphics.rectangle("fill", blip.x, blip.y, blip.size, blip.size)
end

Colors in LÖVE are three numbers from 0 to 1: how much red, green and blue. 0.2, 0.9, 1 is a bright cyan. Run it. A square should sit in the middle of the window.

Step 4Make it move

Movement happens in love.update. The dt it hands you is the number of seconds since the last frame, usually about 0.016. Here's the one rule of smooth movement: multiply every speed by dt. Then a fast computer and a slow one move Blip the same distance per second.

function love.update(dt)
  if love.keyboard.isDown("right") then
    blip.x = blip.x + blip.speed * dt
  end
  if love.keyboard.isDown("left") then
    blip.x = blip.x - blip.speed * dt
  end
end

if ... then ... end is how Lua asks a question. love.keyboard.isDown("right") is true while the right arrow is held. Run it and hold the arrow keys.

Stop for a second. That's the whole secret of every game you've ever played: a number changes, the screen redraws, sixty times a second. Everything else is details. Expensive details, but details.

Now add up and down yourself (remember which way y grows).

Step 5Read the numbers

Debugging means seeing what the computer sees. Add this inside love.draw, after the rectangle:

love.graphics.setColor(1, 1, 1)
love.graphics.print("x = " .. math.floor(blip.x) .. "  y = " .. math.floor(blip.y), 10, 10)

Two new things. .. glues text together. math.floor chops off decimals so the numbers don't jitter. Run it and watch the numbers change as you move. Drive Blip to the top-left and see what the numbers say. Then drive it off the right edge and keep going. Blip is now somewhere around x = 3,000, alone, in the dark. We'll fix that in Ship-It.

Step 6Reacting to a single key press

isDown fires every frame while a key is held. For "do this once when the key is pressed," LÖVE gives you a different function. Add this at the bottom of the file:

function love.keypressed(key)
  if key == "escape" then
    love.event.quit()
  end
end

Now Escape closes the game. Note == with two equals signs: that's "is equal to." One equals sign sets a value; two compare values. Mixing those up is the most common beginner bug in every language, and also the most common Jamie bug, so say it out loud once: one sets, two compares.
