Build 10

Stack Attack, part 1

Ships today

a physics world, a crane that never stops moving, crates that tumble and settle like real crates, and a score that climbs as high as your tower does.

Every game so far, you did the physics by hand: y = y + speed * dt, a box test, a bounce. That's fine for a square named Blip. It is not fine for forty wooden crates landing on each other at angles, which is what Stack Attack needs. So today we hand the physics to Box2D, the engine inside LÖVE that handles gravity, friction, bouncing and tipping over, and we learn to talk to it. Make a new folder, build10-stack-attack, open it in VS Code, and start a fresh main.lua. (Or unzip the starter kit.)

Step 1A world with gravity

function love.load()
  love.window.setTitle("Stack Attack")
  love.physics.setMeter(64)
  world = love.physics.newWorld(0, 9.8 * 64)
  ground = {}
  ground.body = love.physics.newBody(world, 400, 590, "static")
  ground.shape = love.physics.newRectangleShape(800, 20)
  ground.fixture = love.physics.newFixture(ground.body, ground.shape)
  crates = {}
  crane = { x = 400, dir = 1, speed = 220 }
  score = 0
  state = "playing"
end

Three new ideas, all from Box2D. A body is a thing that has a position and can move (or, if it's "static", can't). A shape is its outline. A fixture glues the shape to the body and gives it a surface: friction, bounciness. Every physics object is those three parts. setMeter(64) tells Box2D that 64 pixels is one meter, which is why gravity is 9.8 * 64: Earth gravity, in pixels. The ground is a static body: it holds things up and never moves.

Every frame, the world needs to step forward:

function love.update(dt)
  world:update(dt)
end

Run it. You should see nothing, which is correct. The world is there; nothing's in it yet.

Step 2The crane

The crane is not a physics object. It's a plain table that slides left and right across the top, the way Blip did.

  crane.x = crane.x + crane.dir * crane.speed * dt
  if crane.x > 740 or crane.x < 60 then
    crane.dir = -crane.dir
  end

Draw it as a bar across the top with a little hook under it at crane.x:

function love.draw()
  love.graphics.setColor(0.6, 0.6, 0.65)
  love.graphics.rectangle("fill", 0, 20, 800, 10)
  love.graphics.rectangle("fill", crane.x - 4, 30, 8, 30)
  love.graphics.setColor(0.4, 0.3, 0.2)
  love.graphics.rectangle("fill", 0, 580, 800, 20)
end

Run it. The hook sweeps back and forth. Timing a drop off a moving crane is the entire game; that sweep is where all the tension lives.

Step 3Dropping a crate

A crate is a dynamic body: gravity pulls it, other crates push it, it can tip over.

function dropCrate()
  local c = {}
  c.body = love.physics.newBody(world, crane.x, 70, "dynamic")
  c.shape = love.physics.newRectangleShape(48, 48)
  c.fixture = love.physics.newFixture(c.body, c.shape, 1)
  c.fixture:setFriction(0.8)
  c.fixture:setRestitution(0.1)
  c.w, c.h = 48, 48
  table.insert(crates, c)
end

function love.keypressed(key)
  if key == "space" and state == "playing" then
    dropCrate()
  end
  if key == "escape" then love.event.quit() end
end

The 1 after the shape is density: how heavy the crate is for its size. Friction at 0.8 means crates grip each other instead of sliding off; restitution at 0.1 means they barely bounce. Try 0.9 restitution once, just to watch the tower explode, then put it back.

Step 4Drawing a body

Box2D owns the crate's position and angle now. You ask for them every frame:

  love.graphics.setColor(0.8, 0.6, 0.3)
  for i, c in ipairs(crates) do
    love.graphics.push()
    love.graphics.translate(c.body:getX(), c.body:getY())
    love.graphics.rotate(c.body:getAngle())
    love.graphics.rectangle("fill", -c.w / 2, -c.h / 2, c.w, c.h)
    love.graphics.pop()
  end

push saves the drawing position, translate moves the origin to the crate's center, rotate turns everything by the crate's angle, and pop puts it all back. That's why the rectangle is drawn at -w/2, -h/2: the body's x, y is its center, not its corner. Run it. Drop a crate. Drop another one on top. Drop one on the edge and watch it tip. You wrote none of that physics. That is the payoff of today: forty lines in, and the tower behaves better than anything you could have coded by hand in a month.

Step 5Hearing a landing

Box2D will tell you when two things touch, if you give it a function to call:

function love.load()
  -- after creating the world:
  world:setCallbacks(beginContact)
  landings = 0
end

function beginContact(a, b, contact)
  landings = landings + 1
end

beginContact runs the moment any two fixtures start touching. For now we just count. Print landings in the corner and watch it tick when crates land. (Load a landing sound into thud in love.load, inside pcall so the game still runs without it, and play it here when you have one. Build 11 does the sound pass properly.)

Step 6Score and game over

The score is the height of the tower: the highest crate's top edge, measured from the ground up.

  local best = 590
  for i, c in ipairs(crates) do
    local top = c.body:getY() - c.h / 2
    if top < best then best = top end
    if c.body:getY() > 700 then state = "gameover" end
  end
  score = math.floor((590 - best) / 10)

Lower y means higher on screen, so the smallest top is the tallest point. A crate past y = 700 has fallen off the world, and the tower's done. Print the score big at the top and add a game-over screen with a restart on space, the same state-machine pattern as Meteor Drift. (On restart, call body:destroy() on every crate before emptying the list, or Box2D keeps simulating ghosts.)
