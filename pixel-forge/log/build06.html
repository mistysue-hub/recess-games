Circuit Breaker, part 1

Ships today

a grid of pipe tiles, a mouse that rotates them, a tween you write yourself, and a flood-fill that knows when the power gets through.

Tower Hop was all reflexes. Circuit Breaker is the opposite: nothing moves until you click, and the whole game is one question, is the bulb connected to the battery? Puzzle games teach the most useful trick in this course: a grid is just a list of lists. Make a new folder, build06-circuit-breaker, open it in VS Code, and start a fresh main.lua. No art today; every tile is lines, and it looks better than you'd think.

Step 1The grid

A tile is a table with two facts: its kind and its rot (rotation, 0 to 3, a quarter turn each). The grid is a table of rows, and each row is a table of tiles.

LAYOUT = {
  "CSSSSC",
  "STCSSS",
  "CSTSCS",
  "SCSTSS",
  "TSCSSC",
}
KINDS = { S = "straight", C = "corner", T = "tee" }

function love.load()
  love.window.setTitle("Circuit Breaker")
  COLS, ROWS, SIZE = 6, 5, 90
  OX, OY = 130, 75          -- where the grid starts on screen
  grid = {}
  for r = 1, ROWS do
    grid[r] = {}
    for c = 1, COLS do
      local letter = string.sub(LAYOUT[r], c, c)
      grid[r][c] = { kind = KINDS[letter], rot = math.random(0, 3) }
    end
  end
  source = { r = 1, c = 1 }
  bulb = { r = ROWS, c = COLS }
end

Two loops, one inside the other: the outer walks rows, the inner walks columns. grid[r][c] is the tile at row r, column c. Say it that way every time and you'll never mix them up. (Jamie's grids are always sideways.) string.sub(text, c, c) pulls out the c-th letter, and KINDS turns a letter into a kind name. The letters are the puzzle; the random rot scrambles it. There is a solution hiding in that layout. The top row and the right column are not a coincidence.

Step 2Drawing a tile

Each kind is a few lines from the tile's center. Draw every tile as if rot were 0, then let LÖVE spin it.

function drawTile(tile, x, y)
  love.graphics.push()
  love.graphics.translate(x + SIZE / 2, y + SIZE / 2)
  love.graphics.rotate(tile.rot * math.pi / 2)
  local h = SIZE / 2
  love.graphics.setLineWidth(8)
  if tile.kind == "straight" then
    love.graphics.line(-h, 0, h, 0)
  elseif tile.kind == "corner" then
    love.graphics.line(0, 0, h, 0)
    love.graphics.line(0, 0, 0, h)
  elseif tile.kind == "tee" then
    love.graphics.line(-h, 0, h, 0)
    love.graphics.line(0, 0, 0, h)
  end
  love.graphics.pop()
end

function love.draw()
  for r = 1, ROWS do
    for c = 1, COLS do
      local x, y = OX + (c - 1) * SIZE, OY + (r - 1) * SIZE
      love.graphics.setColor(0.2, 0.25, 0.3)
      love.graphics.rectangle("line", x, y, SIZE, SIZE)
      love.graphics.setColor(0.55, 0.6, 0.65)
      drawTile(grid[r][c], x, y)
    end
  end
end

push, translate, rotate, pop is the cheat-sheet dance: move the origin to the tile's center, spin, draw at 0,0, put everything back. math.pi / 2 is a quarter turn in radians. Run it. A board of grey pipes pointing every which way. That's your puzzle, and you haven't written a single rule yet.

Step 3Clicking a tile

The mouse gives pixels; the grid wants a row and column. Subtract the grid's corner, divide by the tile size, round down, add 1 (Lua lists start at 1).

function love.mousepressed(mx, my, button)
  if button ~= 1 then return end
  local c = math.floor((mx - OX) / SIZE) + 1
  local r = math.floor((my - OY) / SIZE) + 1
  if r < 1 or r > ROWS or c < 1 or c > COLS then return end
  local tile = grid[r][c]
  tile.rot = (tile.rot + 1) % 4
end

% is the remainder: 3 + 1 is 4, and 4 % 4 is 0, so the rotation wraps. The return lines are guards: clear the boring cases first and the real code stays short. Run it and click. Tiles snap a quarter turn. Snapping is fine. Snapping is also how you can tell a game had no budget.

Step 4A tween of your own

A tween is a value sliding from one number to another over time. You could install a library. You will not. It's twelve lines.

tweens = {}

function tween(tile, from, to, duration)
  table.insert(tweens, { tile = tile, from = from, to = to, elapsed = 0, duration = duration })
end

function love.update(dt)
  for i = #tweens, 1, -1 do
    local t = tweens[i]
    t.elapsed = t.elapsed + dt
    local p = math.min(1, t.elapsed / t.duration)
    p = 1 - (1 - p) * (1 - p)          -- ease out: fast start, soft landing
    t.tile.angle = t.from + (t.to - t.from) * p
    if p >= 1 then table.remove(tweens, i) end
  end
end

p runs from 0 to 1; the ease-out line bends it so the tile starts fast and settles gently. angle is the drawn rotation while rot stays the real one. Two changes: in drawTile, rotate by (tile.angle or tile.rot); in mousepressed, after changing rot, call tween(tile, tile.rot - 1, tile.rot, 0.18). Run it. Click. The tile swings into place. That's juice, and you wrote it.

Step 5Which sides are open?

Here's the thinking part. A straight pipe at rot 0 is open left and right; turn it once and it's open top and bottom. Instead of writing every case, write the rot-0 openings once and rotate them.

OPEN = {
  straight = { [0] = true,  [1] = false, [2] = true,  [3] = false }, -- right, down, left, up
  corner   = { [0] = true,  [1] = true,  [2] = false, [3] = false },
  tee      = { [0] = true,  [1] = true,  [2] = true,  [3] = false },
}

function isOpen(tile, side)            -- side: 0 right, 1 down, 2 left, 3 up
  return OPEN[tile.kind][(side - tile.rot) % 4]
end

Sides are numbered clockwise from the right, the way rotate turns. One rotation moves every opening one side clockwise, so to ask "is side 1 open?" on a rotated tile, ask the unrotated tile about side 1 - rot. The % 4 keeps it in range even when negative; Lua's % is kind like that.

Step 6Flood-fill: does the power get through?

Start at the source, mark it powered, and spread: for each powered tile, look at its four neighbors; if this tile is open toward the neighbor and the neighbor is open back, the neighbor is powered too. Keep going until nothing new lights up. That's a flood-fill: paint buckets, minesweeper and every pipe game run on it.

DR = { [0] = 0, [1] = 1, [2] = 0, [3] = -1 }
DC = { [0] = 1, [1] = 0, [2] = -1, [3] = 0 }

function flood()
  for r = 1, ROWS do for c = 1, COLS do grid[r][c].powered = false end end
  local queue = { { r = source.r, c = source.c } }
  grid[source.r][source.c].powered = true
  while #queue > 0 do
    local cur = table.remove(queue, 1)
    for side = 0, 3 do
      local nr, nc = cur.r + DR[side], cur.c + DC[side]
      if nr >= 1 and nr <= ROWS and nc >= 1 and nc <= COLS then
        local here, there = grid[cur.r][cur.c], grid[nr][nc]
        if isOpen(here, side) and isOpen(there, (side + 2) % 4) and not there.powered then
          there.powered = true
          table.insert(queue, { r = nr, c = nc })
        end
      end
    end
  end
end

(side + 2) % 4 is the opposite side. Call flood() at the end of love.load and of love.mousepressed. In love.draw, color a pipe yellow (1, 0.85, 0.3) when tile.powered, draw the bulb's cell as a filled circle that's bright when grid[bulb.r][bulb.c].powered, and print "CONNECTED" at the top when it is. Run it and solve your board. Watch the power creep across the grid one click at a time.
