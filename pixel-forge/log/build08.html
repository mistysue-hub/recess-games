Build 08

Lantern Keep, part 1

Ships today

a keep drawn from a text file, a hero who can't walk through walls, a camera that follows them, and your first class.

Meteor Drift and Tower Hop were one screen each. Lantern Keep is a place: rooms, walls, doors, things on the floor. A place is too big to type in as rectangles, so today the level lives in a text file and the code reads it. Make a new folder, build08-lantern-keep, with three files: main.lua, class.lua, and maps/room1.csv. The starter kit has all three.

Step 1A room is a spreadsheet

Open maps/room1.csv in VS Code: fourteen rows of twenty numbers. 1 is a wall, 0 is floor, 2 is a door. Change a 0 to a 1 in the middle and you've built a pillar. That's level design. Jamie would like a credit.

Reading it is a loop inside a loop:

function loadMap(path)
  local rows = {}
  local text = love.filesystem.read(path)
  for line in text:gmatch("[^\r\n]+") do
    local row = {}
    for num in line:gmatch("[^,]+") do
      table.insert(row, tonumber(num))
    end
    table.insert(rows, row)
  end
  return rows
end

gmatch is a pattern loop: "[^\r\n]+" means "a run of characters that aren't line breaks," so each trip around is one line; "[^,]+" means "a run that isn't a comma," so each trip is one number. tonumber turns the text "1" into the number 1. The result is a list of lists: map[row][col]. Row first, then column, the opposite of x, y. Everyone gets this backwards once.

Step 2Your first class

So far every thing in your games has been a plain table. That works until ten things all need a draw and a move. A class is a recipe for tables that share functions. Lua doesn't have classes built in, so we write ours, in fifteen lines, in class.lua:

local function Class()
  local cls = {}
  cls.__index = cls
  setmetatable(cls, {
    __call = function(c, ...)
      local obj = setmetatable({}, c)
      if obj.init then obj:init(...) end
      return obj
    end
  })
  return cls
end
return Class

Here's the only idea in it. A metatable is a table that tells Lua what to do when it can't find something. cls.__index = cls means: "if an object doesn't have a field, look in the class." So every object made from Entity can call Entity's functions without owning a copy. The __call part lets you write Entity(10, 20) as if the class were a function; it makes an empty object and runs init on it. Now, in main.lua:

local Class = require("class")

Entity = Class()

function Entity:init(x, y, w, h)
  self.x, self.y, self.w, self.h = x, y, w, h
  self.speed = 140
end

function Entity:draw()
  love.graphics.setColor(0.95, 0.85, 0.4)
  love.graphics.rectangle("fill", self.x, self.y, self.w, self.h)
end

The colon in function Entity:draw() is the one from sound:play() in Build 03: it hands the object in as self. player = Entity(3 TILE, 3 TILE, 24, 24) makes your hero. Run it. A yellow square on black. We've been here before; it gets better fast.

Step 3Which tiles are solid

TILE = 32 is the size of one tile on screen. To ask "what tile is under this pixel?" divide and round down:

function tileAt(px, py)
  local col = math.floor(px / TILE) + 1
  local row = math.floor(py / TILE) + 1
  if map[row] and map[row][col] then
    return map[row][col]
  end
  return 1
end

function solidAt(px, py)
  return tileAt(px, py) == 1
end

The + 1 is because Lua lists start at 1 and pixels start at 0. Off the edge of the map counts as wall, so the hero can't fall out of the world. A hero is a box, not a point, so check all four corners:

function boxHitsWall(x, y, w, h)
  return solidAt(x, y) or solidAt(x + w - 1, y)
      or solidAt(x, y + h - 1) or solidAt(x + w - 1, y + h - 1)
end

Step 4Sliding along walls

The naive version moves the hero, then undoes it if they're in a wall. That makes them stick to walls like gum. The fix is to move one axis at a time:

function Entity:move(dx, dy)
  local nx = self.x + dx
  if not boxHitsWall(nx, self.y, self.w, self.h) then
    self.x = nx
  end
  local ny = self.y + dy
  if not boxHitsWall(self.x, ny, self.w, self.h) then
    self.y = ny
  end
end

Try x; if it's clear, take it. Then try y, separately. Walking diagonally into a wall keeps the half of the move that's allowed, so the hero slides. In love.update, build dx and dy from the arrow keys (times speed, times dt) and call player:move(dx, dy). Run it and walk into things. Nothing stops you cold. A wall you can lean on is the difference between a drawing and a place.

Step 5Drawing the keep

First, with no art at all:

function drawMap()
  for row = 1, #map do
    for col = 1, #map[row] do
      local t = map[row][col]
      local x, y = (col - 1) * TILE, (row - 1) * TILE
      if t == 1 then love.graphics.setColor(0.32, 0.30, 0.36)
      elseif t == 2 then love.graphics.setColor(0.55, 0.35, 0.2)
      else love.graphics.setColor(0.16, 0.15, 0.19) end
      love.graphics.rectangle("fill", x, y, TILE, TILE)
    end
  end
end

Now the real art. Download Kenney's Tiny Dungeon pack (the link is in this module), pick the tilemap PNG, and copy it into assets as tiles.png. Its tiles are 16 pixels, so SCALE = 2 doubles them. A quad is a rectangle cut out of a bigger image, which is how one PNG holds a hundred tiles. In love.load:

  local ok, img = pcall(love.graphics.newImage, "assets/tiles.png")
  if ok then
    tileset = img
    quads = {
      [0] = love.graphics.newQuad(0, 0, 16, 16, tileset:getDimensions()),
      [1] = love.graphics.newQuad(16, 0, 16, 16, tileset:getDimensions()),
      [2] = love.graphics.newQuad(32, 0, 16, 16, tileset:getDimensions()),
    }
  end

pcall means "try this, and if it fails, tell me instead of crashing." No image, tileset stays nil, the colored squares carry on. In drawMap, when tileset exists, draw love.graphics.draw(tileset, quads[t], x, y, 0, SCALE, SCALE) instead of the rectangle. The quads above pick the first three tiles of the top row; open the PNG and change 0, 16, 32 to pick ones you like. Jamie picked a skull for the floor. We talked about it.

Step 6The camera

The room is bigger than the window. A camera in 2D is just a shift of everything you draw:

  camX = player.x + player.w / 2 - love.graphics.getWidth() / 2
  camY = player.y + player.h / 2 - love.graphics.getHeight() / 2
  camX = math.max(0, math.min(mapW - love.graphics.getWidth(), camX))
  camY = math.max(0, math.min(mapH - love.graphics.getHeight(), camY))

That's "center on the hero, then clamp so we never show past the room's edge." mapW is #map[1] * TILE. In love.draw, wrap the world:

  love.graphics.push()
  love.graphics.translate(-math.floor(camX), -math.floor(camY))
  drawMap()
  player:draw()
  love.graphics.pop()

Anything between push and pop moves with the camera; anything after pop stays stuck to the screen. math.floor keeps pixel art from shimmering.
