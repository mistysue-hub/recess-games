Build 02

Meteor Drift, part 1

Ships today

a ship, a sky full of falling rocks, fuel to grab, a score, and the one trick behind every game: lists of things. (Next build, the game learns to insult you.)

Blip was one square. Real games have many things: twenty rocks, a hundred bullets. You don't write twenty variables; you write one list and loop over it. Today's game, Meteor Drift, is built on that idea. Make a new folder, build02-meteor-drift, open it in VS Code, and start a fresh main.lua. (Or unzip the starter kit and read along; it's the same code with the Ship-It parts missing.)

Step 1The ship

function love.load()
  love.window.setTitle("Meteor Drift")
  ship = { x = 380, y = 520, w = 40, h = 30, speed = 320 }
  rocks = {}
  fuels = {}
  score = 0
  spawnTimer = 0
end

First, change "Meteor Drift" to whatever you want to call your game. It's your ship; name it. The window title is the first thing anyone sees.

Two new tables, rocks and fuels, start empty. The curly braces with nothing inside mean "a list with nothing in it yet." Draw the ship as a triangle and move it left and right the way you moved Blip, but with math.max and math.min so it stays on screen. (You did that in Build 01; do it again here, it's good practice.)

function love.draw()
  love.graphics.setColor(0.6, 0.9, 1)
  love.graphics.polygon("fill", ship.x, ship.y + ship.h, ship.x + ship.w / 2, ship.y, ship.x + ship.w, ship.y + ship.h)
end

polygon takes pairs of numbers: three corners, six numbers. The ship's x, y is its top-left corner, same as Blip.

Step 2Spawning rocks on a timer

A timer in a game is just a number you add dt to. When it passes a limit, do the thing and reset it.

function love.update(dt)
  spawnTimer = spawnTimer + dt
  if spawnTimer > 0.8 then
    spawnTimer = 0
    local rock = { x = math.random(0, 760), y = -40, w = 40, h = 40, speed = math.random(120, 220) }
    table.insert(rocks, rock)
  end
end

Read that slowly. Every 0.8 seconds we build a new rock table with a random x across the top and a random speed, and table.insert adds it to the end of the list. The local word means "this name only exists inside this block"; use it for anything temporary, which is most things, which is why Jamie never uses it. math.random(a, b) gives a whole number from a to b.

Step 3Loops: do this for every rock

  for i, rock in ipairs(rocks) do
    rock.y = rock.y + rock.speed * dt
  end

ipairs walks the list from first to last. Each time around, i is the position (1, 2, 3...) and rock is that rock's table. Lua lists start at 1, not 0. Drawing uses the same loop:

  love.graphics.setColor(0.7, 0.5, 0.4)
  for i, rock in ipairs(rocks) do
    love.graphics.rectangle("fill", rock.x, rock.y, rock.w, rock.h)
  end

Run it. Rocks should rain. Welcome to the part of game dev where you make a thing and immediately want to dodge it. They never stop falling, though, which brings us to the next problem.

Step 4Removing things safely

Rocks that fall off the bottom should leave the list, or the game slows down after a few minutes and your laptop fan starts making opinions. Removing from a list while walking forward through it skips items (remove item 3 and item 4 slides into slot 3, which you've already passed). Lua will not warn you about this. Lua is very relaxed. So walk backward:

  for i = #rocks, 1, -1 do
    if rocks[i].y > 600 then
      table.remove(rocks, i)
    end
  end

#rocks is how many rocks there are. for i = #rocks, 1, -1 counts down. rocks[i] is the rock at position i. Keep this loop separate from the movement loop; that's fine and clearer.

Step 5Did we hit it? AABB collision

Two rectangles overlap unless one is completely to the left, right, above or below the other. That's the whole test, and it has a name: AABB (axis-aligned bounding box). Put this function at the bottom of the file:

function overlaps(a, b)
  return a.x < b.x + b.w and b.x < a.x + a.w
     and a.y < b.y + b.h and b.y < a.y + a.h
end

return sends the answer back; and means both halves must be true. Now, in the backward loop, before the off-screen check:

    if overlaps(ship, rocks[i]) then
      score = 0
      rocks = {}
      break
    end

Hitting a rock wipes the score and clears the sky (we'll do a real game-over screen in Build 03). break leaves the loop right away, which we need because we just replaced the whole list.

Step 6Fuel and score

Fuel cans spawn like rocks but less often, and touching one is good. Make a second timer, fuelTimer, that spawns a fuel can every 3 seconds, size 24 by 24, speed 150. Move them, remove them off screen, and when the ship overlaps one, add 10 to score and remove that can (table.remove(fuels, i)). Draw them green. Print the score at the top left with love.graphics.print.

You've now written the loop pattern four times: spawn, move, draw, remove. Every game you build from here uses that same pattern. Bullets, coins, enemies, confetti: all lists, all this loop. You've learned more game dev in one build than most people learn before they give up.
