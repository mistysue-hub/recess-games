Circuit Breaker, part 2

Ships today

levels that live in text files, a next-level screen, undo, a flash when the power lands, and three levels nobody but you has ever played. Circuit Breaker becomes a finished game.

Copy build06-circuit-breaker to build07-circuit-breaker and work in the copy. Right now your only level is a table in main.lua. That's fine for one level and terrible for twenty, because every new puzzle means editing code. Real puzzle games keep levels in data files, and the game reads them. Today the game learns to read.

Step 1The level format

Make a folder called levels inside the build folder. Each level is a plain text file. First line: the par (the move count a good solve needs). Every line after that is one row of the grid, two characters per tile: a kind letter, then a rotation digit. L instead of a lowercase letter means locked; we'll use capitals for unlocked and lowercase for locked. Here is levels/level1.txt:

5
t0S3S1S1S3T2
C0T0S0T3S1S0
S1C3S0T2T1S3
S1C0T0T0T1S3
C3C3T3C2S1t1

Read that as a grid. Row 1, tile 1 is t0: a tee, rotation 0, locked. The source sits at the top-left and the bulb at the bottom-right, same as Build 06. The rotation digits are the starting scramble, which means a level designer (you, in about an hour) controls exactly how the puzzle begins. Save a second file, level2.txt, with your own grid of the same size and a par you've actually tested.

Step 2Reading a file

LÖVE reads files from the game folder with love.filesystem.read. It hands back the whole file as one string, newlines included.

function loadLevel(n)
  local text = love.filesystem.read("levels/level" .. n .. ".txt")
  if not text then return false end
  local lines = {}
  for line in string.gmatch(text, "[^\r\n]+") do
    table.insert(lines, line)
  end
  par = tonumber(lines[1])
  grid = {}
  for r = 2, #lines do
    local row = {}
    for c = 1, #lines[r] / 2 do
      local letter = string.sub(lines[r], c * 2 - 1, c * 2 - 1)
      local digit  = string.sub(lines[r], c * 2, c * 2)
      row[c] = {
        kind   = KINDS[string.upper(letter)],
        rot    = tonumber(digit),
        locked = (letter == string.lower(letter)),
      }
    end
    grid[r - 1] = row
  end
  ROWS, COLS = #grid, #grid[1]
  source = { r = 1, c = 1 }
  bulb = { r = ROWS, c = COLS }
  moves = 0
  history = {}
  flood()
  return true
end

string.gmatch(text, "[^\r\n]+") walks the text one line at a time; the odd-looking pattern means "a run of characters that aren't line breaks." tonumber turns "6" into 6; it's a string until you say otherwise. Tile c sits at characters c*2-1 and c*2. The locked line is a small trick: a letter equals its own lowercase only when it already was lowercase. Replace the LAYOUT loop in love.load with level = 1 and loadLevel(level). Run it. Same game, but the puzzle now comes from a file you could email to someone.

Step 3Winning, then the next one

A finished puzzle needs a moment. Add a state, same idea as Meteor Drift: state = "playing" or "won".

function checkWin()
  if grid[bulb.r][bulb.c].powered and state == "playing" then
    state = "won"
    wonAt = love.timer.getTime()
  end
end

function love.keypressed(key)
  if key == "escape" then love.event.quit() end
  if key == "space" and state == "won" then
    level = level + 1
    if loadLevel(level) then
      state = "playing"
    else
      state = "finished"
    end
  end
  -- Step 5 adds undo here
end

Call checkWin() at the end of flood(). In love.draw, when state == "won", print "CONNECTED" big, the move count, and "space for the next level". When state == "finished", print "That's every level. For now." loadLevel returns false when the file doesn't exist, so the game knows it ran out of levels without you having to count them. In mousepressed, add a guard at the top: if state ~= "playing" then return end. Otherwise a click on the win screen keeps rotating tiles underneath it, which Jamie would call "a secret mode."

Step 4Juice

Three small things that make a puzzle feel finished.

The flash. When the bulb first lights, the whole board glows for a moment. In love.draw, before the grid:

  if state == "won" then
    local age = love.timer.getTime() - wonAt
    local glow = math.max(0, 0.6 - age)
    love.graphics.setColor(1, 0.85, 0.3, glow)
    love.graphics.rectangle("fill", 0, 0, 800, 600)
  end

That fourth number in setColor is alpha: how see-through. It starts at 0.6 and fades to 0 over six tenths of a second. The bulb glow. Draw a second, bigger circle behind the bulb with alpha 0.25 when it's powered. The powered pulse. Make powered pipes breathe: their yellow brightness is 0.85 + 0.15 math.sin(love.timer.getTime() 4). sin wobbles between -1 and 1 forever; multiply it by a small number and you get a pulse. Run it. Solve level 1. It feels like a game now, and the only thing that changed is paint.

Step 5Undo

Undo is a stack: every move pushes a record on top; undo pops the top one off and reverses it. Lua lists make this easy. In mousepressed, right before you rotate a tile:

  table.insert(history, { r = r, c = c })

And in keypressed:

  if key == "z" and state == "playing" and #history > 0 then
    local last = table.remove(history)
    local tile = grid[last.r][last.c]
    tile.rot = (tile.rot - 1) % 4
    tween(tile, tile.rot + 1, tile.rot, 0.18)
    moves = moves - 1
    flood()
  end

table.remove(history) with no position takes the last item, which is exactly what a stack wants. Undo a move, and the move counter goes down too; an undo that still cost you a move is the kind of thing players remember. Note what happens to history inside loadLevel: it's emptied, so you can't undo your way into the previous level.
