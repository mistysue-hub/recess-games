Blueprints

Stop describing one pet. Describe what a pet IS, then make as many as you like.

A class is a blueprint. It says what something has (boxes, called fields) and what it can do (methods). An object is one real thing built from the blueprint. One class, many objects.

Program.csC#
1class Pet
2{
3    public string Name;
4    public int Energy = 5;
5
6    public void Speak()
7    {
8        Console.WriteLine($"{Name} says hi! Energy: {Energy}");
9    }
10}
class Petthe blueprint's name. Capital letter by custom.public string Name;a field: every Pet gets its own Name box.public void Speak()a method every Pet can run.

To build an object, use new, then fill its boxes with a dot:

Program.csC#
1Pet cat = new Pet();
2cat.Name = "Mochi";
3cat.Speak();
4
5Pet dog = new Pet();
6dog.Name = "Biscuit";
7dog.Energy = 9;
8dog.Speak();
⚠ HEADS UP
public means "other code is allowed to see this." Leave it off and SHARP hides the field from you, which is confusing the first time. Every class in this course has public on everything.

This is the idea behind almost every game: a Player class, an Enemy class, a Coin class, and hundreds of objects built from them.
