Lots of Things

One box, many items. SHARP starts counting at zero, because of course it does.

A List is a box that holds many items of one type, in order. You can add to it, count it, and grab any item by its position. Lists live in a second toolbox, so programs that use them start with two using lines: using System; and using System.Collections.Generic;

Program.csC#
1List<string> backpack = new List<string>();
2backpack.Add("rope");
3backpack.Add("torch");
4backpack.Add("map");
5Console.WriteLine(backpack.Count);     // 3
6Console.WriteLine(backpack[0]);        // rope
List<string>a list of strings. List<int> would hold numbers.new List<string>()makes the empty list.backpack[0]the FIRST item. Positions start at 0, not 1.
⚠ HEADS UP
Position 0 is the first item, so in a list of 3 the last one is backpack[2]. Ask for backpack[3] and SHARP crashes with an "out of range" error. Everyone does this once.

To visit every item, use foreach. No counter, no positions, SHARP hands you each item in turn:

Program.csC#
1foreach (string item in backpack)
2{
3    Console.WriteLine($"- {item}");
4}

An array is the older, fixed-size cousin. Same zero-counting, but you set the size once and it uses .Length instead of .Count:

Program.csC#
1int[] dice = { 4, 6, 8, 12, 20 };
2Console.WriteLine(dice.Length);   // 5
3Console.WriteLine(dice[4]);       // 20
🔮 PREDICT
The second line of output is backpack.Count. The list has rope, torch, map and snacks. Is Count 3 or 4? (Careful: positions start at 0, but counting doesn't.) Decide, then run.
